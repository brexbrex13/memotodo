# MemoTodo — 付箋ボード

要件をぱぱっと貼り、必要な付箋にだけ期限・通知・業務メモを付ける、Windows用の常駐アプリです。Wails v3の独立した通知ウィンドウを使います。

## 日常の使い方

- ボード上部へ内容を入力し、**Enter**で付箋を貼ります。**Alt+Enter**またはShift+Enterで改行。IMEの変換確定は登録しません。
- 付箋をクリックして、期限、通知時刻、重要マーク、貼る場所、リッチメモを編集します。詳細は自動保存され、保存状態を表示します。
- カテゴリは付箋を貼る場所です。「明日」「今期」「経理」など、仕事に合う場所を作ってください。色・名前を変更できます。
- 付箋は取っ手をドラッグして並べ替えられます。キーボードでは取っ手でSpace、矢印、Space。場所の移動は詳細の「貼る場所」で行います。
- 上部の期限帯は、全カテゴリの期限超過・今日・近日の付箋への入口です。期限のない付箋はボードに残ります。通常の期限近接日数は土日を除く設定が初期値です（祝日は除外しません）。
- 完了するとボードから外れます。「完了・見送り」から再開できます。再開時は古い通知時刻を解除します。削除は「ごみ箱」へ移し、そこから戻せます。
- 検索は内容・メモ・カテゴリ名を対象とします。重要・期限・定期の絞り込みと、手動・期限・重要・新着順を利用できます。
- 太字、文字色、画像、見出し、箇条書き、チェックリスト、HTTP/HTTPSリンクをメモに使えます。画像は貼り付け・ドロップ・ファイル選択に対応し、クリックすると拡大します。
- **Ctrl+N**で追加欄、**Ctrl+F**で検索。×はトレイに格納します。最小化はタスクバーに残ります。完全終了はトレイの「終了（保存して終了）」です。

## 定期タスク

定期設定は、周期ごとに独立した付箋を作るロボットです。未完了分があっても次の付箋が追加され、過去の未完了分は消えません。各付箋の完了・見送り・再開は、その周期だけに作用します。

日・週（複数曜日）・月・年、および周期間隔を指定できます。存在しない月の日付は月末へ調整し、0日指定は常に月末です。「初回期限日」は最初の付箋の正確な期限で、以後は周期設定に従います。終了日はその日を含みます。

それぞれの定期設定に、期限時刻、何日前に付箋を作るか、何日前から期限帯で強調するか、通知方法を保存します。日付だけの期限はその日の23:59:59までです。

例：**水曜までに実施する作業**は、水曜を期限とし「1日前・09:00」を通知に設定すると火曜09:00に知らせます。「24時間前」は期限時刻から24時間を引くため、日付だけの水曜期限なら火曜23:59:59です。この2つは別の設定です。定期設定の日数は暦日です。

通知より後に付箋を作る設定は保存できません。アプリを終了していた期間の付箋・通知は次の起動時に拾います。一時停止中は新しい付箋を作りません。再開時は停止中の期限分を補充せず、今日以降から再開します。設定の編集・終了は既存の付箋を消しません。既に前倒しで作られた付箋は個別に編集してください。

## 通知

通知はメイン画面とは別のウィンドウにまとめて表示します。Windowsでは最前面、タスクバー非表示、表示時のキーボードフォーカス非奪取を指定しています。確認するまで残り、複数件はスクロールして確認できます。

「詳細」はボードを開き、通知を確認済みにはしません。「確認」は通知だけを閉じ、「完了」は付箋を完了します。「10分後」「1時間後」は再通知時刻を保存します。複数の通知を「すべて確認」で閉じられます。まとめ通知は個別スヌーズの代わりに「1時間保留」を利用できます。

通知音、Windows標準通知の併用（初期値OFF）、内容非表示、保留の終了時刻、表示する画面を設定できます。保留中も通知を保存し、解除後に表示します。期限のまとめ通知は平日13:00・17:00が初期値で、空欄で無効になります。復帰後は経過した全時刻を連打せず、当日の最後の時刻のまとめを出します。

アプリの完全終了中は通知を表示できません。PCのロック画面やWindowsのセキュアデスクトップ上にも表示できません。通常の作業中の通知は独自ウィンドウが主手段です。

## 保存とバックアップ

実行ファイル横の`data/board.db`に保存し、画像は`data/images/`に保存します。書き込み可能なフォルダに展開してください。新規アプリとして動作し、旧`todo.db`は読み込まず、変更もしません。旧版のデータ移行・互換性はありません。

詳細の保存失敗時は入力を保持し、閉じる処理を止めます。未保存の詳細と追加欄の入力は下書きとしても保持します。通知側で完了・スヌーズした状態をメモ保存で上書きしないよう、更新を検査します。

設定画面から画像を含むZIPバックアップを作成し、ZIPを選択して復元できます。復元前にも現在のデータを自動退避します。起動時および日付変更時に日次バックアップを作り、10日分を保持します。手動バックアップは自動削除しません。復元対象は50MBまで、展開後200MBまでです。

大きなデータやPC移動は、アプリを完全終了してから`data`フォルダ全体をコピーしてください。起動中のSQLiteファイルだけをコピーせず、画像も含めて扱ってください。未保存の下書きは画面側の保存領域にあるため、移動前に保存済みを確認してください。

## ビルド（Windows・ポータブル版）

Goは`go.mod`指定以上、Node.jsは24以上。Windows 10/11のWebView2 Evergreen Runtimeが必要です。

```powershell
npm ci --prefix frontend
npm test --prefix frontend
npm run build --prefix frontend
go test ./internal/board
go run github.com/tc-hib/go-winres@v0.3.3 make --in build/windows/winres.json --arch amd64 --out rsrc
go build -trimpath -ldflags="-H windowsgui -s -w" -o build/bin/MemoTodo.exe .
```

Wails v3は`go.mod`内のコミットに固定しています。Wails v2のCLI・生成バインディングは使用しません。フロントエンドはv3 runtimeの名前付き呼び出しでGoサービスへ接続します。依存バージョンとlockfileを固定しています。

Linuxでは画面連携検証用に`CGO_ENABLED=0 go build -tags server`を利用できます。`MEMOTODO_DATA_DIR`で保存先、`WAILS_SERVER_HOST`と`WAILS_SERVER_PORT`で検証サーバーの接続先を指定します。サーバーモードはWindowsの最前面・フォーカス検証の代替にはなりません。

GitHub Actionsでロジック、フロントエンド、実サービスとの画面連携、Windowsビルドを検証します。`nativesmoke`タグの専用ビルドは、別プロセスのウィンドウを前面にし、メイン非表示・最小化中の通知、最前面/タスクバースタイル、フォーカス維持、確認までの保持、複数通知をWin32 APIで検証します。結果は`native-smoke.json`に記録します。この検証コードは通常ビルドに含みません。

Actionsの`memotodo-windows-amd64`成果物にポータブルZIPを出力します。タグまたは手動実行のReleaseワークフローもv3対応で、タグの場合はドラフトReleaseを作成します。

合意した設計の要点は[docs/agreed-design.md](docs/agreed-design.md)にまとめています。
