# MemoTodo v3 合意仕様（2026-10-01 UI改修）

会話で修正・合意した最新仕様を基準とする。READMEはユーザーとの文面相談後に別途確定する。

- 旧UIを基礎にカテゴリごとの色付きリスト。常設サイドバーは置かない。
- タイトル入力・Enterで即登録。IME変換確定は登録しない。カテゴリ選択中はそのカテゴリへ追加。
- 左から「定期」「すべて」「各カテゴリ」。「すべて」は通常タスクのみ。除外チェックは置かない。
- カテゴリの色は背景・文字色の組。プリセット、カスタム登録、登録済み配色の管理を提供。カテゴリの管理は右側パネルで順序・表示・名前・配色を制御。
- カテゴリの休眠は表示だけの一時非表示。通知・定期生成・横断期限一覧は止めない。
- タスクの手動並べ替え・カテゴリ間移動・空カテゴリへの移動をD&Dで提供。
- 上部帯は期限超過・今日・近日の横断入口。対象が0件なら非表示。件数から一覧、タスクから詳細へ。ベルは期限順の一覧で、手動順を変えない。
- 上部はベル・…・×の小さなタイトルバー。最小化・最大化なし。×はトレイへ、終了はトレイの右クリック。ウィンドウサイズを記憶。
- 完了済み・ごみ箱・カテゴリ管理・定期設定・設定は…メニューから開く。
- 説明は必要な入力ラベル以外をTIPへ。ホバー待ち時間は200ms。外側クリックでポップアップを閉じる。
- 通常・定期とも期限は日付のみでその日の終わり。通知は独立。期限到達だけでは個別通知しない。
- 定期ルールは期限の繰り返し、タスクリストへの追加日数、通知の日数・時刻を中心にする。初回期限日・期限時刻・強調開始・周期間隔の独立入力・終了日は置かない。
- 定期の追加日数は共通初期値7日前、個別変更可。登録時も残り0〜指定日数の周期分だけ追加。登録以前の過去分は追加しない。
- 定期生成後は永続カーソルで未稼働期間の各周期を拾い、未完了分を残して次周期を追加。重複生成しない。毎週・7日前なら期限当日に翌週分も追加。
- 自動追加のON/OFFは定期設定の一覧にトグルとして配置し、編集フォームには置かない。新規設定はON。停止時は追加停止、既存分は残す。再開は停止中の過去期限を補充せず今日以降へ。編集は今後の分へ適用し、既存分は変えない。
- 近日判定は共通設定に統一。追加日数・通知日数は暦日。通知がタスク追加より先の設定は保存不可。
- 個別通知は小さな独立ウィンドウを縦に並べる。常に最前面・原則タスクバー非表示・フォーカスを奪わず操作まで保持。新着を既存通知へ黙って差し替えない。
- 通知本文と「タスクを開く」で詳細へ。閉じるは通知確認だけ、完了はタスク完了。画面に収まらない分も永続保持し、確認後に順次表示、全件一覧からも操作可能。
- 定時まとめ通知は大きめの独立ウィンドウ。行ごとの完了と「ボードを開く」を提供。「ボードを開く」は当該まとめだけを確認して閉じる。
- 詳細は自動保存。今すぐ保存と×は保存して閉じる。設定類は保存ボタンで確定して閉じる。保存ボタンは下部に常時表示・横幅いっぱい。
- メモは太字・文字色プリセット・画像・リンクを提供。画像選択・クリップボード画像貼り付け・ドロップ。編集欄高さを記憶。HTTP/HTTPS、ローカル・UNCの参照リンクを扱う。
- 新規アプリとしてexe横のdata/board.db・画像へ保存。旧版互換・旧データ移行は不要。既存の本アプリDBは破棄しない。

## 検証境界

Windowsネイティブのフォーカス・最前面・タスクバー・物理クリックはWindowsで検証する。Linuxのserverモードは業務ロジック・画面連携の検証であり、ネイティブ動作の代替にはならない。
